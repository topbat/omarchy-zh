# Omarchy 中文手册站设计说明

## 目标

在 `D:\self\omarchy-zh` 中建立一套非官方简体中文 Omarchy 手册站。站点完整覆盖官方目录页和 51 个章节页面，保持原站的终端视觉、左侧章节导航、搜索、代码展示、图片、表格、标题锚点和前后页导航。

## 内容边界

- 上游内容以 `basecamp/omarchy` 仓库 `quattro` 分支的固定提交为基线。
- 将官方 `manual/*.md` 与 `manual/images/*.webp` 保存为可审计的上游快照。
- 中文内容逐文件映射到同名章节，不删除段落、列表、表格、链接、图片或代码块。
- 命令、快捷键、路径、参数、配置键、代码块和品牌名称保持原样。
- 标题、说明性正文、导航、搜索、图片替代文本和表格说明翻译为简体中文。
- 页面明确标注“非官方简体中文翻译”，保留 MIT 许可证和来源链接，不复制官方统计代码。

## 信息架构

- `/manual/`：第 1 章“欢迎使用 Omarchy”。
- `/manual/toc/`：完整中文目录页，按 01–51 编号。
- `/manual/<slug>/`：其余 50 个章节，slug 与官方保持一致。
- 每章桌面端显示搜索框与粘性左侧目录；正文区显示当前章节、标题锚点、内容和前后页导航。
- 移动端保留搜索入口、正文和前后页导航，章节目录通过“目录”链接进入完整列表页。

## 视觉系统

- 直接以官方页面、样式表和页面资源作为视觉真值，不新增风格。
- 保留黑色终端背景、白色标题、青色链接、绿色章节编号、等宽字体、圆角代码块与图片。
- 桌面断点保持双栏结构：约 17em 章节栏与约 44em 正文栏。
- 小于 64em 时切为单栏，正文宽度、代码横向滚动和图片比例保持稳定。
- 所有字体、样式、图片和脚本本地化，不使用远程热链。

## 技术架构

- Node.js 静态站生成器负责读取 Markdown、生成路由、目录、标题锚点、前后页导航、搜索索引、站点地图和静态资源。
- `markdown-it` 负责 Markdown 渲染；高亮只作用于代码显示，不改写代码文本。
- 原生 CSS 复刻官方设计，原生 JavaScript 实现搜索、`/` 聚焦、Escape 关闭结果和移动端行为。
- 输出目录为 `site/`，本地开发服务器固定支持历史回退和目录索引。

## 数据流

1. 读取固定上游快照并核对章节顺序。
2. 读取一一对应的中文 Markdown。
3. 解析标题、slug、正文、标题锚点、链接、图片与代码块。
4. 生成 51 个章节页面、目录页、搜索索引和静态资源。
5. 自动校验上游与译文的结构一致性。

## 翻译质量规则

- 使用统一术语表，首次出现的专业缩写可采用“中文术语（英文缩写）”。
- Omarchy、Arch Linux、Hyprland、Quickshell、Neovim、Chromium 等专名不翻译。
- TUI、GUI、CLI、API、SSH、VM 等缩写保留。
- `Super + Space`、`~/.config/...`、命令行、配置片段和 URL 原样保留。
- 代码块按规范化文本与上游逐块比对，任何差异均阻断交付。

## 验收

- 自动化：51 个章节、44 张图片、82 个图片引用、39 个代码块全部通过一致性检查。
- 链接：内部路由、锚点、图片和相对链接无断链。
- 内容：检测空译文、待翻译标记和大段英文漏译；代码与专名不误报。
- 浏览器：原站与本地站分别在 1440×900、390×844 下截图；验证搜索、目录、前后页、代码滚动和移动端无横向溢出。
- 设计 QA：将同尺寸源站截图和实现截图组合对比，修复所有 P0/P1/P2 问题后才能交付。

## 已知约束

- 原站内容可能随 `quattro` 分支更新。本项目保存上游提交号，并提供差异检查，不在构建时静默拉取新内容。
- 已存在的第三方中文仓库只作为术语和译文参考；最终译文必须通过本项目自己的结构与语言检查。
