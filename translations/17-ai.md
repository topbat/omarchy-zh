# AI

Omarchy 将 AI 编码代理视为一等公民，但不会替你选定最喜欢的代理。相反，每个主要的编码代理 CLI 都预先配置为延迟加载启动器。这些启动器是由 [mise](https://mise.jdx.dev/) 管理的微型存根，位于 `~/.local/bin/` 中，因此在你首次实际运行某个代理之前不会下载任何内容。调用以下任意命令，并在提示时完成身份验证：

| Command    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | Grok CLI from xAI                                                |
| `pi`       | [Mario Zechner's Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), OpenRouter's harness(代理执行框架) |

`ori` 是个例外：它会让其他代理执行框架使用 OpenRouter 的完整模型目录运行，因此 `ori claude`、`ori codex` 或 `ori opencode` 会根据你指定的模型启动这些代理，而 `ori code` 则是 Ori 自己的代理。

要以相同方式包装另一个 CLI，请运行 `omarchy-mise-install <package> [command-name]`。运行 `omarchy update`（或 `mup` 别名）时，存根会与 mise 管理的其他所有内容一起保持最新。

### 默认代理

使用 `omarchy default agent <name>`，或在 Omarchy 菜单（`Super + Space`）的 _Setup > Defaults > Agent_ 下选择默认代理。如果代理尚未安装，选择它时会先安装。全新的 Omarchy 会通过一次性通知邀请你进行选择。

选择之后，`Super + Shift + Ctrl + A` 会在专用终端窗口中启动默认代理（如果你尚未选择，则调出选择器）。你也可以使用 `omarchy agent prompt "Review this project"` 直接让它开始执行任务。以这种方式启动的代理会在自动批准模式下无人值守运行，因此请做好它们实际执行操作的准备！另外，由于代理拒绝记住对主目录的信任，从 `$HOME` 启动时会改为从 `~/Work` 开始。

终端中也有快捷方式：`a` 会在当前终端内运行默认代理，而 `c`、`cx` 和 `cy` 会直接启动 OpenCode、Claude Code 和 Codex（同样处于自动批准模式）。主题变化也会同步到代理：切换 Omarchy 主题时，Claude Code、Pi 和 OpenCode 都会跟随变化。

### 代理面板

Omarchy 首次发现机器上有 AI 编码使用记录时，顶栏会增加一个代理图标（在此之前它会一直保持隐藏，不干扰使用）。图标后面的面板会集中跟踪每项订阅：你的方案、5 小时会话和每周限额的使用百分比（或剩余预付余额），以及按天和按模型统计的令牌使用量。Claude Code、Codex 和 Fireworks 开箱即用。

左键点击顶栏图标打开面板，右键点击启动默认代理。使用记录由 `omarchy agent usage-update` 每 15 分钟重新生成一次，面板甚至可以通过同步文件夹合并来自其他机器的使用量。完整设置请参阅 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 以捕获进程崩溃。当发生段错误时，你会收到“Process crashed”通知；点击它，崩溃信息就会连同 Omarchy 的 diagnose-crash skill 一起交给默认代理，该 skill 会引导代理根据核心转储确定事实，并判断是否值得向上游报告。你也可以针对 `coredumpctl list` 中的任意 PID 手动运行 `omarchy agent crash <pid>`。

监视功能默认开启。在 _Trigger > Toggle > Crash Capture_ 下关闭它（或运行 `omarchy toggle crash-capture`），通知就会停止；但 `omarchy agent crash <pid>` 仍可手动使用。

### 桌面应用

_Install > AI_ 菜单还提供几个图形化 AI 应用：ChatGPT 桌面应用，以及用于与 xAI 模型聊天的 Grok Bot。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供图形界面，用于查找开放权重模型、安装模型并运行模型。这是轻松入门的好方法。Ollama 则提供 CLI 来完成类似操作。但如果你刚接触本地模型，我建议从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装其中任意一个。

### Omarchy Skill

代理 skill 帮助 AI 以特定方式使用特定工具，而 Omarchy 附带一个用于定制系统的默认 skill，例如调整 Hyprland 配置、调整顶栏，甚至从头创建新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）以及通用的 `~/.agents/skills` 位置，因此大多数 harness 都会自动发现它。

但你应该将此 skill 视为实验性功能。不同模型对它的使用效果各不相同。最好先在计划模式下运行，这样你可以了解代理想要修改什么。然后要准备好回滚修改；如果代理把一切弄得一团糟，甚至可以调用 `omarchy reinstall configs`。
